项目用来组织需要多条 [任务](/issues) 一起完成的工作，例如一次产品发布、一次迁移，或一个分阶段推进的功能。

一条任务能说清的工作不需要项目。项目适合有共同目标、需要统一跟进进度，或需要共享仓库和工作目录的一组工作。

## 项目的组成

| 内容 | 用途 |
|---|---|
| **名称、图标和描述** | 目标、范围和长期有效的要求；描述会进入项目内智能体的执行上下文。 |
| **状态** | `planned`、`in_progress`、`paused`、`completed` 或 `cancelled`。 |
| **优先级** | `urgent`、`high`、`medium`、`low` 或 `none`。 |
| **负责人（lead）** | 成员或智能体，表示谁负责协调项目。 |
| **开始和截止日期** | 项目计划的时间范围。 |
| **任务和进度** | 项目中的工作及其完成比例。 |
| **资源** | 关联的 GitHub 仓库或指定电脑上的本地目录。 |
| **工作流** | 任务经过哪些步骤，以及每一步由谁接手。 |

## 项目和任务的关系

一个项目可以包含多条任务，一条任务最多属于一个项目。可以在项目中直接创建任务，也可以在任务属性中选择或更换项目。

项目进度按关联任务自动计算：

```text
进度 = 状态属于 done 或 closed 分类的任务数 ÷ 项目中的全部任务数
```

内置状态里就是 `done` 和 `cancelled`，归入这两个分类的自定义状态也一样计入。`cancelled` 表示这项工作已从项目范围中结束，所以算进进度。

项目状态和任务状态各管各的：所有任务完成后，项目不会自动变为 `completed`；修改项目状态，也不会批量修改其中的任务。

## 项目描述与执行上下文

智能体执行项目内的任务时，项目名称和描述会加入本次执行的上下文。所有相关运行都需要知道的信息写在描述里，比如目标、技术边界、交付约定；只与单条任务相关的要求写在那条任务中。

## Specs & Docs 文档

在网页或桌面端的项目中打开 **Specs & Docs 文档**，按核心 Spec 规范、项目指南与纪要分组浏览，或检索标题、REQ 编号和正文。新建 Spec 会带入背景与目标、需求、WHEN/THEN 场景和验收清单模板，也可以创建普通空白文档。

**阅读/直编**、**双栏对照**、**源码**操作同一份 Markdown。快捷按钮可插入需求、场景和验收项；直编视图中的验收勾选同步到 Markdown。点击**保存修订**或按 Cmd/Ctrl+S 提交新版本；未保存的修改保留为当前设备的草稿，切换文档、返回项目及刷新后仍可恢复。放弃修改需要确认。

右栏展示最近的人类与智能体编辑者、可解析的项目资源引用和修订历史。**版本对比**包含双方标题与正文。遇到冲突时，可以保留草稿、另存本地副本，或对比并确认基于已查看的版本保存；若远端再次更新，保存仍会被拒绝。

项目运行可发现文档资源，并通过与界面相同的 API 读取最新已保存的修订：

```bash
multica project document list <project-id> --output json
multica project document get <project-id> <document-id-or-uri> --output markdown
multica project document create <project-id> --kind spec --title "功能规范"
multica project document update <project-id> <document-id> --base-version 2 --title "功能规范" --body-file ./spec.md
multica project document history <project-id> <document-id>
```

`--base-version` 必须是实际读取过的版本。收到 409 后先读取并对比新版本，再重新提交。引用格式为 `multica://project/<project-id>/documents/<document-id>`，可用 `project document get` 读取；资源接口 `GET /api/projects/{id}/resources/{resourceId}/content` 也能解析最新内容。浏览器中未保存的草稿不会提供给运行。

## 添加资源

项目资源告诉智能体使用哪些代码和工作目录：

- **GitHub 仓库**：提供可 checkout 的仓库和可选 ref。
- **本地目录**：让指定电脑上的运行时在已有目录中工作，目录内容会被智能体直接修改。

具体选择和安全边界见[项目资源](/project-resources)。

## 选择工作流

项目的**工作流**决定看板有哪些列，以及任务进入每一步时交给谁。例如开发交给一个智能体，审查交给另一个，最后交给成员验收。没有选用其他工作流时，使用 **Default**：所有状态都可用，也不会自动交接。创建流程和切换已有项目的方法见[工作流](/workflows)。

## 项目负责人

项目负责人可以是成员或智能体，担任负责人的成员还可以为项目切换工作流。设置负责人不会把任务分配给它，也不会启动任何工作；想让某一步交给项目负责人，在工作流里把这一步的处理人设为**项目负责人**。

## 固定到侧边栏

固定后，项目出现在你的侧边栏中。固定是个人偏好，不影响其他成员。

## 创建、编辑和删除

工作区成员都可以创建和编辑项目；只有 `owner` 和 `admin` 可以删除。

<Callout type="warning">
删除项目不会删除其中的任务：它们解除关联后继续保留在工作区；项目的描述、状态和资源会被永久删除。
</Callout>
