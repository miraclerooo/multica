小队由一名队长智能体和若干成员组成。把任务分配给小队后，不会同时运行所有智能体：Multica 先唤醒队长，由它阅读上下文，决定下一步交给谁。

小队只负责把工作交给合适的人。它不会把多个智能体合并成一个新的智能体，也不会自动提高并发。

## 适用场景

当工作需要多种能力，而且不能在创建任务时就确定具体负责人，可以使用小队。例如，一个产品交付小队可以包含前端、后端和测试智能体，由队长根据每条任务的内容分配。

工作范围明确时，直接分配给对应的[智能体](/agents)即可。

## 小队的组成

| 配置 | 作用 |
|---|---|
| **队长** | 必须是一名智能体。接收分配给小队的工作，并决定如何处理。 |
| **成员** | 可以是智能体，也可以是人类成员。同一成员可以加入多个小队。 |
| **角色说明** | 告诉队长每个成员适合处理什么工作。它只是上下文，不会授予权限或自动触发成员。 |
| **小队指令** | 保存路由规则、协作方式和需要贯穿全队的背景，只会提供给队长。 |

创建小队时需要填写名称并选择队长。队长会自动成为小队成员；之后可以继续添加成员、填写角色说明和小队指令。

## 分配后的执行流程

非 backlog 状态的任务分配给小队后，Multica 会立刻给**队长智能体**入队一次运行（不是给每个成员都入一个）：

1. **队长的运行时领走运行**，和普通智能体的分配流程一样。
2. **队长拿到 briefing。** 运行被领取时，Multica 会在队长的指令后面追加三段内容，见下文[队长每次执行看到的内容](#队长每次执行看到的内容)。
3. **队长发一条派活评论。** 评论里用花名册给好的 mention markdown `@` 选中的成员。被 `@` 的智能体会入队一次新运行，被 `@` 的人类成员会收到通知。
4. **队长记录 evaluation**：`multica squad activity <issue-id> <outcome> --reason "..."`。这一行会写进任务的 activity 时间线，方便人类回溯队长的每次评估。
5. **派活轮让父任务处于 `in_progress`。** 和直接分配给智能体同一套状态约定：协调小队就是在推进父任务本身的工作，所以父任务从 `todo` 进入 `in_progress`；派活不等于交付，小队干活期间保持不变。
6. **队长停下。** 派完活，队长不亲自动手。被派成员有回复时，队长会被自动唤醒，决定下一步：继续派活、上抛给人类、在整体目标达成后把父任务推到 `in_review`，或保持沉默。`done` 留给人工确认或既有集成（例如带 close intent 的 PR merge）。

如果任务仍在 `backlog`，分配本身不会触发队长。移出 `backlog` 后才会开始执行。

### 队长每次执行看到的内容

每次队长被触发，三段内容会附加到它的指令上：

- **Squad Operating Protocol（小队工作规范）**：一段硬编码的规则集，读任务 → 用 `@` 派活 → 保持简洁（不复述任务内容，被派的成员自己能读）→ 每次记 evaluation → 派完就停（派活轮结束时父任务处于 `in_progress`）→ 整体目标达成后才推 `in_review`。这段由系统管理，不可编辑。

 其中状态相关的规则只对"确实分配给本小队"的任务生效。队长被别人任务里的 `@小队` 唤醒时，同样拿到花名册和派活规则，但会被明确告知不要改动那条任务的状态，状态仍归那条任务自己的负责人。
- **Squad Roster（小队花名册）**：队长一行，加上每个未归档成员一行，每行带可直接复制的 mention markdown（`[@Name](mention://agent/<uuid>)`）。纯文本 `@name` 不会触发任何人。
- **Squad Instructions（小队指令）**：你为这个小队写的自定义内容，包括路由规则（"数据库相关派给 Alice，前端派给 Bob"）、上报策略，或任务本身不会有的背景。

## 队长的再次触发时机

第一次派活之后，大多数后续评论会自动唤醒队长：

| 事件 | 触发队长 | 说明 |
|---|---|---|
| 非小队成员（人类、外部智能体）发评论 | 会 | |
| 小队成员发进展更新，不带任何 `@` | 会 | 队长重新评估下一步 |
| 任何评论里显式 `@` 了智能体、成员、小队或 `@all` | 不会 | 显式 `@` 就是路由信号，队长让位 |
| 队长自己发的评论 | 不会 | 防止自己触发自己 |
| 评论里只有任务互链 | 会 | 任务引用不算路由 |

在这些规则之上还有去重：如果队长在这条任务上已有处于排队或已领取状态的运行，新触发不会重复入队。

<Callout type="info">
成员发的 `@` 评论不唤醒队长，是因为直接 `@` 已经是明确的交接，再唤醒队长只会多一轮空转。例外：智能体发结果时顺手 `@` 了另一个智能体，队长仍会被唤醒，以便协调整条线程。
</Callout>

## 分配小队和 @小队

| 操作 | 是否改变负责人 | 结果 |
|---|---|---|
| **把任务分配给小队** | 是 | 小队成为负责人，并触发队长。 |
| **在评论中 @小队** | 否 | 只让队长处理这条评论，原负责人不变。 |

直接 @某名成员时，工作会交给该成员处理。

## 小队与 Access

把智能体加入小队不会绕过它的 [Access](/agents#权限与-access)。普通成员创建或管理小队时，只能选择自己有权运行的智能体。

成员能否分配或 @某个小队，取决于其是否有权运行小队的队长。若队长已归档，或当前成员无权运行它，这个小队就无法被分配或 @提及。

## 创建与管理权限

任何工作区成员都可以创建小队。创建者可以修改和归档自己创建的小队；工作区 `owner` 和 `admin` 可以管理所有小队。

小队名称不要求在工作区中唯一。更换队长时，新队长会自动加入小队；当前队长不能直接移除，需要先指定另一名队长。

## 归档小队

归档后，小队会从列表、负责人选择器和 @菜单中消失，也不能恢复。

为避免现有工作失去负责人，当前分配给小队的任务和自动化会转给原队长智能体。历史评论和活动记录仍然保留。如果之后还需要相同的路由，需要重新创建小队。

<Callout type="warning">
归档操作无法撤销。
</Callout>

## 流水线模式

“流水线”页签管理命名流水线及各自的版本。“新建流水线”和“编辑流水线”在弹窗中打开，默认显示“流程图”，可切到“源码”查看完整 YAML。新建时预填四步 GitLab 草稿，已有 Hermes 定义继续按原格式编辑。

直接选择节点或连线打开属性。“添加节点”可选择执行节点或人工审批；节点默认显示基本设置，完整指令单独编辑，内部 ID 和阶段收起到高级设置。修改显示名称不会重命名内部节点或改变顺序。取消或切换选择会保留尚未应用的字段，保存流水线前需应用或明确丢弃。可以拖动连接点连线，也可用键盘或触摸激活连接点后选择两端。

执行者列出全部小队智能体，包括角色为空的成员，也保留动态队长和已有角色绑定。指定成员后不会自动替换成队长。调用权限与运行环境就绪情况分别检查，不兼容或缺失的环境会如实提示。人工审批可搜索工作区人类成员，新节点默认使用当前登录者的真实用户身份；已有未解析审批人会保留，只有明确选择才替换。审批人接收通知，不绕过原有审批权限。

预期文件分别填写文件名与多行说明。段落会在源码、草稿、版本、材料和 Markdown 关联中保留。同名文件用完整路径区分，只有声明不代表已经发布交付物。

“保存版本”生成不可变定义；“保存并启用”同时设为未来运行的默认版本，已有运行保留原定义和材料。检查栏中的“执行模式”单独管理小队默认，不在目录中设置。没有已保存流水线时会打开可编辑的默认预览，明确保存并启用前不生效。切回指引模式会保留小队指引。Mika 提议完整草稿，由你校验并明确发布。

任务中的流水线卡可打开运行记录、节点 attempt、日志和实际交付物。人工节点等待上游和必需材料就绪后才能审批，拒绝必须填写意见。审批保留固定文档版本、附件或仓库 SHA。缺少价格时显示“未计价”。

项目文档按来源任务分组。将已发布交付物关联到已有或新建 Markdown 文档，会插入正文链接并保存来源。重复操作不重复插入链接；解除任务关系会保留正文、源文件和历史。并发编辑时保留草稿供比较。

同一小队可以保存多条命名流水线，各自拥有独立版本历史。选择流水线后可编辑或重命名；单独保存版本不会更改小队默认。请单独设置默认，或明确选择“保存并启用”。

创建小队任务时，可沿用默认、明确使用指引，或选择具体流水线。预览显示准确版本与相关运行环境的就绪情况。等待中的任务保留该版本，不受后来发布的新版本影响。在已创建的任务中重检并继续已保存的执行，无需再建任务。界面分别显示 daemon 与已安装 CLI 的身份；按提供的更新操作或部署指引自行处理后，再次重检。

Web 与 Desktop 共用编辑器。移动端“更多 → 流水线”支持命名流水线、YAML 编辑、版本与默认设置；新建任务页支持执行选择和继续。流程图编辑与 Mika 编写仍在 Web/Desktop 使用。

在流程图中可新增执行节点或人工门禁，编辑完整属性，并通过连接点或连线表单连接。YAML 与画布共用一份草稿和撤销历史。删除节点前会展示引用影响；阶段推导依赖改为显式 needs 时需要确认。无法安全映射的结构可回到 YAML 保留和修改。历史版本与运行图只读，画布编辑不要求升级 CLI。

## 使用 CLI

```bash
multica squad create --name "Product Delivery" --leader delivery-lead
multica squad member add <squad-id> \
 --member-id <agent-or-member-id> \
 --type agent \
 --role "负责前端实现"
```

完整命令见 [使用 CLI](/cli)。
